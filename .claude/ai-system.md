# AI-система: промпты, агенты, регламент

## Как устроены промпты

```
lib/prompts/
  regulation.ts    ← РЕГЛАМЕНТ (единственный файл для правки правил протокола)
  sgr-prompts.ts   ← промпты агентов с плейсхолдерами
```

### Инжекция регламента

**Регламент** (`PROTOCOL_REGULATION`) подключается в двух местах:

1. **Document Agent** (`document-agent.ts`):
   ```ts
   SGR_DOCUMENT_AGENT_PROMPT
     .replace('{{REGULATION}}', PROTOCOL_REGULATION)
     .replace('{{CONVERSATION_CONTEXT}}', conversationContext)
     // ...
   ```

2. **Chat Agent** (`chat-agent.ts`): добавляется как отдельное системное сообщение перед историей диалога:
   ```ts
   messagesWithUserPrompt.push({ role: "system", content: PROTOCOL_REGULATION });
   ```

**Чтобы изменить правила протокола** — редактировать только `lib/prompts/regulation.ts`. Оба агента подхватят изменения автоматически. Никакие промпты трогать не нужно.

## Три промпта в системе

### 1. SGR_MAIN_AGENT_PROMPT — чат-агент (разговорная часть)

**Назначение:** сбор данных для протокола через диалог, раздел за разделом.

**Ключевые принципы:**
- **SGR (Schema-Guided Reasoning):** агент рассуждает по внутренней JSON-схеме, но пользователю показывает только `output.proposed_content`. JSON-схему в чат НИКОГДА не выводить.
- **Один раздел = одно сообщение.** Нельзя в одном ответе смешивать разделы 3 и 4.
- **Максимум 1 вопрос** за ответ.
- **Тайм-коды** `[ТС: ЧЧ:ММ:СС]` — обязательны для каждого факта из расшифровки в чате.
- **Пропускать приветствие** если уже есть расшифровка (файл или >1 сообщений).
- Инструмент `publishInvestigationProtocol` вызывается только при явной просьбе "сформируй/сделай протокол".

**Порядок сбора разделов:**
```
1. Шапка (номер, дата, название, договор)
2. Повестка
3. Участники (Заказчик + Исполнитель)
4. Содержание встречи (Слушали/Обсудили/Решили) + Резюме
5. Согласовано (подписанты)
```

**Хранится в:** SurrealDB (таблица `prompt`, `isDefault=true`). Если пользователь выбрал другой промпт → берётся из БД по ID.

### 2. SGR_DOCUMENT_AGENT_PROMPT — агент генерации документа

**Назначение:** одним вызовом LLM создать структурированный JSON протокола из всей истории диалога.

**Плейсхолдеры:**
```
{{REGULATION}}              → lib/prompts/regulation.ts
{{CONVERSATION_CONTEXT}}    → вся история чата (строка)
{{EXISTING_DOCUMENT_CONTEXT}} → текущая версия документа (если были ручные правки)
{{AGREED_CHAT_CONTEXT}}     → блоки подтверждённые пользователем ("верно")
```

**Выход:** чистый JSON без markdown-обёрток. Структура — `ProtocolSchema` (Zod).

**КРИТИЧНО:** промпт требует JSON без ` ```json ``` `, без объяснений до/после, корневые поля — сразу в объекте без вложенного ключа `"protocol"`.

### 3. SGR_CLASSIFIER_PROMPT — классификатор intent

**Назначение:** определить `chat` или `document` для edge-cases.

**Вход:** история диалога + последнее сообщение пользователя.
**Выход:** `{"type":"chat|document","confidence":0.0-1.0,"reasoning":"..."}` — чистый JSON.

**Правило document:** только явная просьба ("сформируй", "сделай", "подготовь протокол", "выведи в документ"). Просто загрузить файл или ответить "ок" → всегда `chat`.

## PROTOCOL_REGULATION — структура и назначение

Файл: `lib/prompts/regulation.ts`

Содержит правила согласно корпоративному регламенту:
- Стиль текста (официально-деловой, третье лицо, не стенограмма)
- Аббревиатуры (ТЗ→Техническое задание, разрешены: 1С:БГУ)
- Повестка: отглагольные существительные (Согласование, Утверждение...)
- Слушали: только ФИО через запятую
- Обсудили: кто инициировал, позиции сторон (не дублировать Решили)
- Решили: действие + дата (ДД.ММ.ГГГГ) + ответственный; запрет расплывчатых формулировок
- Резюме: таблица со Срок: и Ответственный: в каждой строке
- Заказчик/Исполнитель с заглавной буквы

## Пользовательские промпты

Пользователи могут создавать свои варианты системного промпта через UI.

**Хранение:** SurrealDB, таблица `prompt`
- `isDefault=true` → дефолтный промпт (нельзя редактировать/удалять)
- `userId` → промпт принадлежит конкретному пользователю
- Пользователь может выбрать активный промпт — хранится в `user_selected_prompt`

**API:** `GET/POST/PUT/DELETE /api/promts`

**Загрузка в route.ts:**
```ts
resolveSystemPrompt(userId, selectedPromptId)
// 1. selectedPromptId → из БД
// 2. userId → getUserSelectedPrompt() → из БД
// 3. дефолт → getPrompt() (кешируется в памяти)
```

**Важно:** регламент (`PROTOCOL_REGULATION`) инжектируется независимо от выбранного промпта — всегда добавляется как системное сообщение в chat-agent. Даже если пользователь выбрал кастомный промпт, регламент действует.

## Модели и провайдеры

**Resolver:** `lib/resolve-chat-model.ts`

| Условие | Провайдер |
|---------|-----------|
| `OPENROUTER_API_KEY` задан | OpenRouter |
| Иначе | Ollama (локальный) |

**Ollama (по умолчанию):**
- URL: `OLLAMA_BASE_URL` (default: `http://127.0.0.1:11434/v1`)
- Модель: из `ALLOWED_OLLAMA_MODELS` или `qwen3.5:9b`
- Контекст: `OLLAMA_CONTEXT_LENGTH` (default: 131 072)

**Параметры streamText:**
```ts
temperature: 0.7, topP: 0.8, presencePenalty: 1.5  // chat-agent (Qwen3 рекомендации)
temperature: 0.1                                      // document-agent (детерминированность)
```

**Лимиты вывода:**
```
OLLAMA_MAX_OUTPUT_TOKENS              → общий лимит
OLLAMA_FILE_TURN_MAX_OUTPUT_TOKENS    → первый ответ после файла (короче)
OLLAMA_PROTOCOL_MAX_OUTPUT_TOKENS     → генерация документа
```

## Обработка ошибок LLM

**Кривой JSON от LLM:**
1. `parseProtocolStrict(rawFinal)` → если упало
2. `extractNoObjectGeneratedText(objErr)` → текст из ошибки Vercel AI SDK
3. `parseLooseJsonObject(text)` → loose JSON парсер (находит {...} в тексте)
4. Если всё упало → throw с понятным сообщением пользователю

**coerceProtocolPartial():** нормализует частичный Protocol во время стриминга:
- Русские имена полей → английские
- Строки вместо массивов → `[string]`
- Вложенный `protocol.{}` → разворачивает
- Заглушки типа "Не указано" в participants → пустые массивы
