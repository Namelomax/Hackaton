# Живой тест протоколера — 27.07.2026

Стенд: https://hackaton-kappa-seven.vercel.app/ , режим «☁️ Облако + анонимизация», модель `nvidia/nemotron-3-ultra-550b-a55b:free`.
Тестовые данные: `test_probely_transcript.txt` — расшифровка с намеренными пробелами («вчера», «сегодня», «до конца недели», безымянное учреждение, безымянный чат, «доработать форму» без деталей, участник без фамилии).

## Что работает

- **Анонимизация**: 15 упоминаний ПДн → 5 плейсхолдеров, даты сохранены (как договорились), деанонимизация в ответе корректная.
- **Маркеры уточнений в документе (п.3 заказчика)** — работают. В сформированном протоколе появились:
  - `учреждение (наименование ⚠️ требует уточнения)`
  - `в рабочем чате (наименование ⚠️ требует уточнения)`
  - `на следующей неделе (⚠️ требует уточнения: конкретная дата)`, `вчера (⚠️ требует уточнения: конкретная дата)`
  - `Срок: ⚠️ требует уточнения` в каждом решении и в резюме
  - `Тема договора: ⚠️ требует уточнения`
- **Финальная сверка** после генерации отдельным сообщением перечисляет относительные даты — полезно.

## Найденные проблемы

### 1. Правка/Retry теряют документ и conversationId (главная причина «правая панель не обновляется»)

Перехват тела запросов `/api/chat`:

| Путь | documentContent | conversationId | selectedPromptId |
|---|---|---|---|
| обычная отправка | есть (5913 симв.) | есть | есть |
| ✏️ правка сообщения / Retry | **нет** | **нет** | **нет** |

Агент не видит текущий протокол → правки применять не к чему.
**Исправлено**: `app/page.tsx` → `buildRetryBody()`, используется в `handleEdit` и `handleRegenerate`.

### 2. Повторная ошибка не показывается вообще (тишина вместо ответа)

`onError` в `app/page.tsx` навсегда запоминал сигнатуру последней ошибки и молча гасил такую же. На стенде: отправка правки → `/api/chat` 500 → **ни ответа, ни ошибки, ни изменений в панели**. Ровно тот симптом, что описывает заказчик.
**Исправлено**: дедуп сведён к окну 3 секунды (эхо одного запроса).

### 3. Ложное «Проверь OPENROUTER_API_KEY»

При 500 Next.js отдаёт HTML-страницу ошибки; парсер подстрок ловил в разметке признаки 401 и показывал ошибку про API key.
**Исправлено**: HTML-страница ошибки распознаётся отдельно, текст про 500 и объём контекста.

### 4. 500 FUNCTION_INVOCATION_FAILED в генерации документа

Логи Vercel: последняя строка перед падением — `[generateFinalDocument] maxOutputTokens=8192`, подпись `FUNCTION_INVOCATION_FAILED`. В соседнем запросе та же причина попала в catch и вернула 200:

```
Document generation error: AI_NoObjectGeneratedError: No object generated: could not parse the response.
text: '', finishReason: 'other'
cause: AI_JSONParseError: Unexpected end of JSON input
```

Модель (бесплатный слаг Nemotron) отдаёт **пустой ответ**. В `document-agent.ts` промис `streamResult.object` подписывался только ПОСЛЕ полного разбора `partialObjectStream`. Когда провайдер отваливается сразу, промис отклоняется в момент, когда подписчика ещё нет → unhandledRejection → Vercel убивает функцию, клиент получает 500 и HTML вместо стрима. Try/catch вокруг не помогает: реджект вне его цепочки.

**Исправлено**:
- обработчик к `streamResult.object` вешается сразу после `streamObject(...)` (`objectSettled`), разбор результата — как раньше, но уже из settled-значения;
- пустой ответ модели даёт понятное сообщение вместо стектрейса;
- при падении генерации в правую панель возвращается предыдущая версия протокола (раньше `data-clear` уже прошёл и документ терялся).

### 5. Протоколер не делает документ после первого круга вопросов

Договорённость с заказчиком: после первичных вопросов по структуре — сразу документ, дальше уточнения по тексту. Фактически агент задал **два** круга вопросов и сформировал протокол только после прямого «больше вопросов не задавай». Причина — «Поток диалога» в `SGR_MAIN_AGENT_PROMPT`: Шаг 2 (сроки/ответственные) и Шаг 3 (подписанты) блокировали генерацию.
**Исправлено в промте** (`lib/prompts/sgr-prompts.ts`): Шаг 2 = повестка + немедленный вызов инструмента, недостающее уходит в документ как «⚠️ требует уточнения»; Шаг 3 = уточнения уже по готовому документу (включая подписантов). Требует проверки после деплоя.

### 6. Имя инструмента протекает в чат

Ответ пользователю содержал: «После ваших ответов сразу сформирую протокол через publishInvestigationProtocol».
**Исправлено в промте**: прямой запрет упоминать инструмент.

### 7. Правка без вызова инструмента

В промте правки требовали повторять раздел текстом. Добавлено правило: если документ уже сформирован, любая правка обязана заканчиваться повторным вызовом инструмента публикации.

## Не исправлено, на заметку

- **«Всегда локальная модель» при правке**: клиент отправляет `chatProvider: "openrouter"` корректно (проверено перехватом). Переключение происходит на сервере — `app/api/chat/route.ts:894-902`: если анонимизатор недоступен, провайдер молча меняется на `ollama` с уведомлением «отвечаю через локальную модель». На пути правки/Retry клиентский preview `/api/anonymize` не вызывается, весь текст анонимизируется внутри запроса — при таймауте сервиса это срабатывает чаще.
- **Правка/Retry в облачном режиме не показывают окно «Проверка перед отправкой в облако»**, хотя галочка включена. Анонимизация на сервере выполняется, но подтверждения пользователь не видит.
- **Имена из чата не мапятся на плейсхолдеры**: на «Сергея включай» модель ответила «Сергея в расшифровке не встречается» — в облако ушёл `[PERSON_4]`, а склонённое «Сергея» не подставилось. Нужна морфологическая нормализация при forward-подстановке.
- **Путаница сторон**: Дмитрий Величко в таблице «Заказчик», а в тексте раздела 4 — «Исполнитель (Дмитрий Величко)».
- **Retry затирает готовый протокол** в правой панели на время генерации; при падении запроса документ остаётся пустым.

## Проверить после деплоя

1. Правка сообщения → в теле `/api/chat` есть `documentContent` → панель обновляется.
2. Две одинаковые ошибки подряд → обе видны в чате.
3. Ответ на первый блок вопросов → документ формируется сразу, без второго круга.
4. Генерация протокола 3–5 раз подряд на облачном слаге: 500 не должно быть ни разу — при пустом ответе модели ожидается сообщение в чате и сохранённая прошлая версия документа.
5. Прогнать `npm run build` локально (полный typecheck в песочнице не успел завершиться).

## Рекомендация по модели

`nvidia/nemotron-3-ultra-550b-a55b:free` регулярно отдаёт пустой ответ на JSON-генерации протокола (2 падения + 1 пустой ответ за один сеанс). Для `ANONYMIZER_CLOUD_MODEL` стоит взять платный слаг или добавить авто-ретрай с запасной моделью.
