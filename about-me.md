## Ключевые проекты

**Протоколер** — AI-ассистент для составления протоколов встреч. Пользователь грузит расшифровку совещания, ведёт диалог с агентом, получает готовый протокол в DOCX по корпоративному регламенту.

- Стек: Next.js 15 (App Router), React 19, Vercel AI SDK v5, SurrealDB (WebSocket), Tailwind 4 + shadcn/ui, Biome, Jest.
- Модели: Ollama (Qwen3) / OpenRouter, локальный self-hosted инференс.
- Архитектура агентов: main-agent (роутер chat vs document) → chat-agent (диалог + инструменты) → document-agent (JSON → DOCX), плюс orchestrator/classifier для intent.
- Отдельные слои: RAG (внешний FastAPI-сервис), Zod-схема Protocol с коэрцией кривого JSON от LLM, генерация DOCX локально.
- Регламент — единый источник правил (`lib/prompts/regulation.ts`), инжектится в промпты через плейсхолдер.

**anonymizer** (privacy-filter) — обратимая анонимизация PII для русского языка. Находит чувствительные данные, меняет на плейсхолдеры `[LABEL_N]`, хранит JSON-маппинг, детерминированно восстанавливает исходник без модели.

- Python-пайплайн: `detectors` (регэкспы для ИНН/СНИЛС/паспорт/контакты) → разрешение пересечений спанов → присвоение плейсхолдеров → маппинг.
- NER/ФИО/адреса через GLiNER (в т.ч. на GPU/JupyterHub), веб-интерфейс, бенчмарк и контрактные тесты.

## Как я работаю с моделями и агентами

- **Код-гарды важнее послушания промпта.** Слабая модель не всегда слушается инструкции — поэтому критичные инварианты закрываю детерминированным кодом (guards), а не надеждой на промпт. Пример: запрещённые/выдуманные сроки в протоколе принудительно превращаются в «подлежит уточнению».
- **Чат — источник истины.** Подтверждённое пользователем в диалоге должно побеждать регенерацию модели; модель добивает только пустые поля, а не перетирает подтверждённое.
- **Structured output с подстраховкой.** LLM часто возвращает кривой JSON → нормализация/коэрция перед валидацией схемой (Zod).
- **Промпт-инжиниринг и SGR** (Schema-Guided Reasoning) — системные промпты агентов с плейсхолдерами регламента, отдельные промпты под chat- и document-агента.
- **Локальные и self-hosted LLM.** Работаю с Qwen3, Gemma через Ollama (в т.ч. проксированный self-hosted эндпоинт), OpenRouter как альтернативный провайдер. Учитываю бюджет контекста (для Qwen3 — лимит 131k, резерв под системный промпт/ответ; русский ≈ 2.34 симв/токен).
- **Верификация — офлайн + живой прогон.** Код проверяю офлайн (`tsc`, Jest, контрактные тесты), но поведение чата и финальный документ прогоняю вживую на своей машине — из песочницы LLM недоступен. Чёткое разделение «зелёный код» ≠ «проверенное поведение».

## Стиль работы и предпочтения к ассистенту

- **Кратко и по делу.** Минимум воды и лишних объяснений; убери слово — если смысл не потерялся, оно лишнее.
- **Честно про границы.** Явно разделять, что проверено, а что нет; не выдавать «зелёный tsc» за работающее поведение.
- **Тесты и проверка — обязательный шаг.** Предлагать верификацию (юнит/контрактные тесты, живой прогон, диффы).
- **Детерминизм > магия.** Где можно закрыть инвариант кодом — закрывать кодом, а не промптом.
- **Русский по умолчанию.** Отвечать и писать документы на русском.
- **Хорошие точки для git-коммита** отмечать после связного блока правок.
