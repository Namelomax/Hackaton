# Автогенерация названий чатов через LLM

Дата: 2026-09-12
Статус: утверждён к реализации

## Проблема

Каждый новый диалог создаётся с заголовком `'Чат'`
(`ensureConversationCreated`, `components/chat/PromptInputWrapper.tsx:168`).
В сайдбаре список выглядит как десяток одинаковых строк «Чат», отличимых
только по дате — найти нужное совещание невозможно.

Осмысленное имя сейчас появляется лишь постфактум и только в памяти браузера:
`normalizeConversationTitle` (`app/page.tsx:327`) вытаскивает H1 из уже
сгенерированного протокола. До готового документа — и после перезагрузки, если
документа нет — заголовок остаётся дефолтным. В БД производное имя не пишется.

Ручное переименование уже работает: `PUT /api/conversations` с полем `title` →
`renameConversation` (`lib/getPromt.ts:797`).

## Цель

После первого же сообщения пользователя чат называется по теме обсуждения. Если
приложена расшифровка совещания — по названию этого совещания.

## Принятые решения

| Развилка | Решение |
|----------|---------|
| Момент генерации | Сразу после отправки первого сообщения, фоновым запросом параллельно основному ответу |
| Провайдер модели | **Всегда локальная Ollama**, независимо от режима чата |
| Повторная генерация | Один раз. Не-дефолтный заголовок (в т.ч. переименованный вручную) не трогаем |
| Место генерации | Отдельный эндпоинт, а не поток `/api/chat` |

### Почему всегда Ollama

В режиме «Облако + анонимизация» чат ходит в OpenRouter, но туда уходит только
текст, прошедший анонимизатор. Генерация названия происходит до/помимо этого
пайплайна и работает с сырой расшифровкой, поэтому отправлять её во внешний
провайдер нельзя — это утечка ПДн мимо контура (152-ФЗ). Локальная модель
снимает вопрос целиком. Если Ollama недоступна — работает детерминированный
фолбэк без модели (см. ниже), названия не пропадают.

### Почему отдельный эндпоинт, а не `/api/chat`

`app/api/chat/route.ts` — тысяча с лишним строк: роутинг агентов, RAG,
анонимизация, два параллельных SSE-потока. Встраивание туда означало бы:

- имя чата привязано к жизненному циклу стрима (отменил генерацию — нет имени);
- ошибка генерации имени способна повлиять на основной ответ;
- роут в облачном режиме уже работает через OpenRouter, а нам нужна Ollama.

Отдельный роут независим, дёшев и переиспользуем (кнопка «переименовать через
ИИ» позже подключается к нему же без изменений).

## Архитектура

### Компоненты

```
components/chat/PromptInputWrapper.tsx   ← новый проп onAutoTitle, вызов после sendMessage
app/page.tsx                             ← реализация колбэка: дедупликация + fetch + setConversationsList
app/api/conversations/title/route.ts     ← НОВЫЙ роут: гарды, идемпотентность, вызов LLM, запись в БД
lib/chat-title.ts                        ← НОВЫЙ: чистые функции (сборка исходника, санитайзер, фолбэк)
lib/prompts/sgr-prompts.ts               ← новый SGR_CHAT_TITLE_PROMPT
lib/getPromt.ts                          ← новый getConversationTitle()
lib/__tests__/chat-title.test.ts         ← НОВЫЙ: юнит-тесты чистых функций
```

### Поток данных

1. `handleSubmit` (`PromptInputWrapper.tsx:470`) уже получил `ensuredConversationId`
   и вызвал `sendMessage(...)`. Сразу после этого — **без await** —
   `void onAutoTitle?.({ conversationId, text: textWithQuote, files: finalFiles })`.
2. Колбэк в `page.tsx` знает `conversationsList` и `authUser`:
   - пропускает, если `conversationId` начинается с `local-`;
   - пропускает, если `!isGenericChatTitle(conv.title)`;
   - пропускает, если id уже в `autoTitleInFlightRef` (`Set<string>`);
   - иначе `POST /api/conversations/title`.
3. Роут генерирует название, **сам** сохраняет его через `renameConversation`
   и возвращает `{ success: true, title }`.
4. Колбэк по ответу делает
   `setConversationsList(prev => prev.map(c => c.id === id ? { ...c, title } : c))`
   и снимает id из `autoTitleInFlightRef`.

Сохранение делает сервер, а не клиент: иначе между генерацией и `PUT` был бы
второй круг сети, на котором пользователь успевает уйти/закрыть вкладку.

### Эндпоинт `POST /api/conversations/title`

**Тело запроса**

```ts
{
  conversationId: string;
  text?: string;                     // текст сообщения пользователя
  files?: Array<{                    // те же FileUIPart, что уходят в /api/chat
    id?: string; filename?: string; url?: string;
    mediaType?: string;
  }>;
  userId?: string;
}
```

**Ответ**

```ts
{ success: true, title: string, generated: boolean }   // generated=false → фолбэк или skipped
{ success: false, message: string }
```

**Шаги обработки**

1. `resolveRequestUserId(req, body.userId)` — личность только из подписанной
   сессии, как в соседних роутах.
2. `assertConversationOwnership(conversationId, userId)`; `ForbiddenError` → 403,
   любая другая ошибка гарда → 503 (не 500 и не «пропустить»). Копируем схему
   из `app/api/conversations/route.ts:98-111`.
3. **Идемпотентность на сервере.** `getConversationTitle(conversationId)`; если
   `!isGenericChatTitle(current)` — сразу
   `{ success: true, title: current, generated: false }`, ничего не пишем.
   Это защита и от гонки двух вкладок, и от затирания ручного переименования:
   клиентская проверка на шаге 2 предыдущего раздела — оптимизация, а не гарантия.
4. Сборка исходника: `buildTitleSource(text, attachmentTexts)`, где тексты
   вложений получены через `extractAttachmentTextCached` (`lib/attachment-extract.ts:228`).
   Кэш общий с `/api/chat`, поэтому docx/pdf не разбирается второй раз.
5. Вызов модели:
   ```ts
   const model = resolveChatLanguageModel({ chatProvider: 'ollama', useThinking: false });
   const { text } = await generateText({
     model,
     temperature: 0.2,
     maxOutputTokens: 120,
     prompt: SGR_CHAT_TITLE_PROMPT.replace('{{SOURCE}}', source),
   });
   ```
   `maxOutputTokens` **обязателен**: без него fetch-обёртка подставляет
   `ollamaHardCapOutputTokens()`, и шлюз отвечает 400 ещё до генерации — та же
   грабля, что подробно разобрана в `app/api/chat/agents/classifier.ts:107-117`.
6. `sanitizeGeneratedTitle(text)`; при `null` — `fallbackTitleFromSource(source)`.
7. `renameConversation(conversationId, title)` и ответ клиенту.

Любая ошибка LLM ловится и уводит на фолбэк, а не в 500: не назвать чат
идеально — мелочь, но оставить его «Чатом» из-за упавшей модели не нужно.

### Новый хелпер БД

```ts
/** Текущий заголовок диалога, либо null если записи нет. */
export async function getConversationTitle(convId: string): Promise<string | null>;
```

В `lib/getPromt.ts`, рядом с `renameConversation`. Читает одну запись через
`db.select(new RecordId('conversations', clean))` — по образцу
`assertConversationOwnership`. Ошибку чтения **пробрасывает**, а не глотает:
молча вернуть `null` значило бы «заголовок дефолтный» и разрешить перезапись
чужого имени при сбое базы.

### `lib/chat-title.ts`

Чистые функции без сетевых вызовов — их и покрываем тестами.

```ts
/** Склейка текста сообщения и вложений, обрезка до лимита. */
export function buildTitleSource(
  text: string | null | undefined,
  attachmentTexts: Array<string | null | undefined>,
  limit = 4000,
): string;

/** Ответ модели → пригодный заголовок, либо null если ответ мусорный. */
export function sanitizeGeneratedTitle(raw: string | null | undefined): string | null;

/** Детерминированный запасной заголовок из исходного текста. */
export function fallbackTitleFromSource(source: string): string | null;
```

**`buildTitleSource`** берёт **начало** текста, а не конец: шапка расшифровки с
темой, датой и повесткой всегда сверху. Порядок — сначала текст сообщения
(если пользователь сам написал, о чём речь, это самый сильный сигнал), затем
вложения. Лимит 4000 символов ≈ 1700 токенов по проектной оценке 2.34 симв/токен —
с запасом влезает даже при холодном кэше.

**`sanitizeGeneratedTitle`** по шагам:

1. срезать `<think>...</think>` (Qwen3 отдаёт их даже при `useThinking: false`);
2. взять первую непустую строку;
3. снять обрамляющие кавычки (`" ' « » “ ”`) и служебные префиксы
   («Название:», «Заголовок:», «Тема:»);
4. снять точку в конце (вопросительный/восклицательный знак оставить);
5. схлопнуть пробелы;
6. если длина > 60 — обрезать по последней границе слова так, чтобы итог
   **вместе с добавленным `…`** был не длиннее 60 символов;
7. вернуть `null`, если результат пуст, короче 3 символов или сам проходит
   `isGenericChatTitle`.

**Кириллица.** Все регулярки здесь пишутся на явных классах `[а-яёА-ЯЁ]`.
`\w` и `\b` в JS ASCII-only: `/\bТема\b/` не матчится никогда, а `\w+` рвёт
русские слова. Это уже приводило к тихим багам в проекте — повторять нельзя.

**`fallbackTitleFromSource`** — первая непустая строка исходника, прогнанная
через тот же санитайзер. Даёт «Стенограмма совещания от 12.09» вместо «Чат»,
когда модель недоступна.

### Промпт

`SGR_CHAT_TITLE_PROMPT` в `lib/prompts/sgr-prompts.ts`, рядом с остальными
системными промптами (правило проекта: поведение AI меняется только там).
Требования к формулировке:

- ответ — **только** название, без пояснений, кавычек и префиксов;
- 2–6 слов, русский язык;
- отражает тему совещания или запроса, а не факт «пользователь прислал файл»;
- без ФИО и должностей — в сайдбаре они не нужны, а в облачные логи не попадут
  тем более (генерация локальная, но правило оставляем);
- плейсхолдер `{{SOURCE}}` — как во всех остальных промптах файла.

### Что остаётся без изменений

`normalizeConversationTitle` (`app/page.tsx:327`) не трогаем. Он срабатывает
только на generic-заголовках, поэтому сгенерированное имя его переживает, а
если модель и фолбэк промолчали — H1 готового протокола по-прежнему
подстраховывает отображение.

`getChatSidebarLabel` / `isGenericChatTitle` (`lib/chat-display.ts`) остаются
единственным определением «дефолтного» заголовка и переиспользуются и на
клиенте, и в новом роуте.

## Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Чужой диалог | 403, ничего не пишем |
| Проверка владения не удалась | 503, ничего не пишем |
| Заголовок уже не дефолтный | 200, `generated: false`, БД не трогаем |
| Ollama недоступна / таймаут | Фолбэк-заголовок, 200, `generated: false` |
| Модель вернула мусор | Фолбэк-заголовок |
| Фолбэк тоже пуст (сообщение из одних эмодзи) | 200, `title: 'Чат'`, `generated: false` — как сейчас |
| Сеть с клиента отвалилась | Тихо, только `console.warn`. Заголовок останется дефолтным, пользователь ничего не теряет |

Клиентский колбэк никогда не показывает toast: это фоновое удобство, а не
операция пользователя, и ругаться на неё в интерфейсе неуместно.

## Тестирование

`lib/__tests__/chat-title.test.ts` — Jest, только чистые функции:

- `sanitizeGeneratedTitle`:
  - вырезает `<think>…</think>` и берёт то, что после;
  - снимает кавычки-ёлочки и префикс «Название:»;
  - многострочный ответ → только первая строка;
  - слишком длинный ответ → обрезка по границе слова + `…`, итоговая длина ≤ 60;
  - `null` на пустой строке, на `'Чат'`, на `'Новый чат 3'`;
  - кириллица не ломается (проверка ровно того, что раньше ломал `\w`).
- `buildTitleSource`:
  - соблюдает лимит и режет с конца, а не с начала;
  - пустые/`null` вложения пропускаются;
  - текст сообщения идёт перед текстом вложений.
- `fallbackTitleFromSource`:
  - берёт первую значимую строку;
  - `null` на пустом исходнике.

Роут не покрывается юнит-тестами: он состоит из вызовов уже покрытых гардов и
одного обращения к модели. Проверяется вручную по сценариям ниже.

## Ручная проверка

1. Новый чат → сообщение «Составь протокол по совещанию о переносе сроков
   поставки» → через 1–2 с в сайдбаре осмысленное имя вместо «Чат».
2. Новый чат → приложить .docx с расшифровкой без текста сообщения → имя из
   темы совещания.
3. Переименовать чат вручную → отправить ещё сообщение → имя не изменилось.
4. Режим «Облако + анонимизация» → имя всё равно генерируется, в логах
   OpenRouter запроса на заголовок нет.
5. Остановить Ollama → имя приходит из фолбэка, чат работает.
6. Перезагрузить страницу → имя на месте (значит, записано в БД).

## Вне объёма

- Кнопка «Переименовать через ИИ» в меню чата. Роут её поддержит без изменений
  (нужен будет только флаг обхода проверки идемпотентности), но в этой задаче
  не делаем.
- Перегенерация названия по мере развития диалога.
- Названия для чатов, созданных до этой правки: старые «Чат» так и останутся.
